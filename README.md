# Maritime Job Agent

Автономный агент поиска морских вакансий (Captain/Master, Bulk Carrier
Capesize и выше, от $10,600/мес). Работает по расписанию через GitHub
Actions — не требует включённого компьютера. Найденные новые вакансии
приходят одним письмом-дайджестом на email; если новых нет — письмо не
отправляется вовсе.

**Логика типа судна (обновлено 2026-08-31):** т.к. явное указание класса
"Capesize"/"Newcastlemax"/"VLOC" в объявлениях встречается редко, вакансия
на просто "Bulk Carrier" тоже проходит фильтр, если в карточке НЕ указан
DWT меньше 150 000 (т.е. либо DWT ≥ 150 000, либо DWT/класс не упомянуты
вовсе). В последнем случае письмо помечает такую строку
"⚠️ класс судна не указан — проверьте вручную", чтобы можно было
самостоятельно отсеять то, что не подходит. Судно, у которого DWT прямо
указан и меньше 150 000, по-прежнему отсеивается. Подробности — в
`evaluate_vessel()` (`parsers/base.py`) и комментариях в `config.yaml`.

## Статус источников (реальный прогон 2026-11-03, коммит `f363d2b`)

Запуск каждый час (`17 * * * *`). Цифры — вакансий/постов за один прогон до фильтра.

| Источник | Статус | За прогон | Комментарий |
|---|:-:|:-:|---|
| UkrCrewing | ✅ | 302 | 10 страниц `/en/vacancy/pN/` |
| Maritime Union | ✅ | 150 | `maritime-union.com/jobs?p=N` |
| Martide | ✅ | 90 | разделы `/jobs/master`, `/jobs/bulk-carriers/master` |
| Crewell | ✅ | 60 | `?page=1..5` |
| SeaJobs.ru | ✅ | 50 | `/ru/vacancies?page=N` |
| Telegram | ✅ | ~50 | каналы из `telegram_channels` в config.yaml, посты не старше 10 дней |
| Berge Bulk, Oldendorff, TURTLE, Columbia | ✅ | 1–6 | карьерные страницы компаний |
| JobMarineMan | ⚠️ | 0 | 403 анти-бот; включается вход на портал моряка, если заданы Secrets `JMM_LOGIN`/`JMM_PASSWORD` |
| SeaCareer, FindSeafarer | ⚠️ | 0 | ссылки на вакансии не находятся |
| Maritime-Zone | 🛑 выкл. | — | 403 на всё, включая страницу входа |

В логе каждого запуска (Actions → шаг *Run job agent*) перечислена каждая
вакансия капитана с причиной решения фильтра: `ДА`, `НЕТ: зарплата …`,
`НЕТ: судно …`.

## Как это устроено

```
main.py                        — точка входа: вызывает все парсеры, фильтрует,
                                  дедуплицирует, отправляет письмо
config.yaml                    — критерии фильтрации (должность, тип судна,
                                  зарплата, флаг, контракт) — редактируется
                                  без изменения кода
mailer.py                      — отправка письма через Gmail SMTP
seen_vacancies.json            — ID уже отправленных вакансий (для дедупликации),
                                  коммитится обратно workflow после каждого запуска
parsers/
  base.py                      — общие утилиты: модель Vacancy, HTTP-клиент,
                                  парсинг зарплаты/типа судна, generic HTML-скрапер
  martide.py                   — по одному файлу на каждый сайт-источник
  jobmarineman.py
  crewell.py
  maritime_zone.py
  turtle.py
  findseafarer.py
  seacareer.py
  berge_bulk.py
  oldendorff.py
  columbia_shipmanagement.py
.github/workflows/daily-check.yml — расписание: 00:00 UTC = 08:00 Asia/Kuala_Lumpur
```

## ⚠️ Важно про статус проверки парсеров

Этот проект собирался в изолированной песочнице **без доступа в интернет**,
поэтому HTML-структура сайтов-источников не могла быть проверена вживую в
момент написания кода. Каждый парсер:

- никогда не падает молча и не "тихо" возвращает пустой список без причины —
  если ссылок на вакансии не нашлось, в логах будет явное предупреждение
  вида `[source] На странице ... не найдено ни одной ссылки на вакансию`;
- использует общий устойчивый механизм (`generic_html_job_scrape` в
  `parsers/base.py`), а не жёстко прибитые CSS-классы, поэтому переживает
  мелкие изменения вёрстки лучше, чем точечные селекторы;
- обёрнут в `try/except` и логирует полную ошибку через `logger.exception`,
  не останавливая остальные источники.

**Перед тем как полагаться на письма от агента, прогоните workflow вручную
хотя бы один раз** (см. ниже) и проверьте логи — какие источники реально
вернули вакансии, а какие требуют доработки селекторов или защищены от
скрапинга.

### Как запустить тестовый прогон вручную

1. Откройте вкладку **Actions** репозитория на GitHub.
2. Выберите workflow **Daily Maritime Job Check**.
3. Нажмите **Run workflow** (кнопка справа, ветка `main` или ваша рабочая).
4. После завершения откройте лог шага **Run job agent** — там для каждого
   источника будет строка `[source] Получено вакансий: N` или предупреждение
   о причине сбоя.

### Диагностика парсера, если источник вернул 0 вакансий

1. Посмотрите текст предупреждения в логе — он говорит, что искалось
   (`href_patterns`) и по какому URL.
2. Откройте `LISTING_URL` этого источника в браузере, нажмите "Просмотр
   кода страницы" (Ctrl+U) и найдите там реальные ссылки на вакансии —
   сравните с `HREF_PATTERNS` в соответствующем файле `parsers/<source>.py`,
   поправьте паттерны.
3. Если в исходном HTML вообще нет ссылок на вакансии (список подгружается
   JS-скриптом после загрузки страницы) — откройте вкладку браузера
   **DevTools -> Network -> Fetch/XHR**, обновите страницу и найдите запрос,
   который возвращает JSON со списком вакансий. Обычно проще и надёжнее
   дёргать этот JSON-эндпоинт напрямую (через `requests`), чем HTML.
4. Если сайт отдаёт капчу / блокирует запросы по User-Agent / требует логин
   — это защита от скрапинга. Тогда:
   - проверьте, нет ли у сайта публичного RSS/Atom-фида вакансий (часто
     `/feed`, `/rss`, `/vacancies.rss`) — RSS почти никогда не защищён капчей;
   - либо проверьте, не отдаёт ли компания вакансии через сторонний ATS
     (Workday, Greenhouse, SmartRecruiters, Lever и т.п.) — у них обычно
     есть публичный JSON API по прямой ссылке;
   - если ничего из этого не подходит — сообщите об этом и рассмотрите этот
     источник как "нерабочий по объективной причине" (отключите его в
     `config.yaml`: `sources.<name>.enabled: false`), а не пытайтесь обойти
     капчу.

## Настройка секретов (Gmail)

Секреты **никогда** не хранятся в коде — только в GitHub Secrets репозитория
(Settings -> Secrets and variables -> Actions -> New repository secret):

| Имя секрета          | Значение                                                    |
|-----------------------|--------------------------------------------------------------|
| `GMAIL_ADDRESS`       | Ваш Gmail-адрес, от которого отправляются письма             |
| `GMAIL_APP_PASSWORD`  | Пароль приложения Gmail (см. ниже, НЕ обычный пароль!)       |
| `MAIL_TO` (опционально) | Адрес получателя, если отличается от `GMAIL_ADDRESS`       |
| `JMM_LOGIN`, `JMM_PASSWORD` (опционально) | Логин и пароль JobMarineMan (портал моряка) |

### Как получить/обновить Gmail App Password

1. Включите двухфакторную аутентификацию на аккаунте Google (обязательное
   условие для app password): https://myaccount.google.com/security
2. Перейдите на https://myaccount.google.com/apppasswords
3. Создайте новый пароль приложения (тип — "Другое", назовите, например,
   `maritime-job-agent`), скопируйте 16-значный код.
4. В репозитории на GitHub: **Settings -> Secrets and variables -> Actions**
   -> найдите `GMAIL_APP_PASSWORD` -> **Update** -> вставьте новый код.
5. Старый пароль приложения можно отозвать на той же странице Google
   (`Remove`), если он был скомпрометирован или больше не нужен.

## Как поменять критерии поиска

Всё — в `config.yaml`, код трогать не нужно:

```yaml
filters:
  positions: [captain, master]        # должности
  vessel_types: [capesize, ...]       # ключевые слова типов судна
  dwt_min: 150000                     # порог DWT, если тип судна не назван словами
  min_salary_usd: 11000               # минимальная зарплата
  include_unknown_salary: true        # включать вакансии без указанной зарплаты?
  flags: []                           # флаг судна, [] = без ограничений
  contract_lengths: []                # длительность контракта, [] = без ограничений
```

Изменения применяются со следующего запуска workflow (или сразу — при
ручном запуске `Run workflow`).

## Как добавить новый сайт-источник (11-й, 12-й и т.д.)

На примере добавления гипотетического сайта **NewJobsSite**
(`https://newjobssite.com/vacancies`):

1. Создайте файл `parsers/newjobssite.py`:

   ```python
   from __future__ import annotations
   import logging
   from .base import Vacancy, generic_html_job_scrape

   logger = logging.getLogger("maritime_job_agent")

   SOURCE = "newjobssite"
   LISTING_URL = "https://newjobssite.com/vacancies"
   HREF_PATTERNS = ["/vacancy/", "/job/"]  # подстроки, по которым узнаём ссылку на вакансию

   def fetch_vacancies(config: dict) -> list[Vacancy]:
       try:
           return generic_html_job_scrape(
               source=SOURCE,
               listing_url=LISTING_URL,
               href_patterns=HREF_PATTERNS,
               config=config,
               title_hint_words=["master", "captain"],
           )
       except Exception:
           logger.exception("[%s] Не удалось получить вакансии", SOURCE)
           return []
   ```

2. (Опционально) добавьте `newjobssite: { enabled: true }` в секцию
   `sources:` в `config.yaml` — если не добавить, источник всё равно
   включён по умолчанию (`enabled: true`).

3. Всё. `main.py` найдёт новый файл автоматически через
   `pkgutil.iter_modules` — его код менять не нужно.

Если у сайта совсем нестандартная вёрстка и `generic_html_job_scrape` не
справляется — пишите собственную логику внутри `fetch_vacancies()`, единственное
жёсткое требование — интерфейс: принимает `config: dict`, возвращает
`list[Vacancy]` (класс `Vacancy` — в `parsers/base.py`), и никогда не бросает
исключение наружу.

## Локальный запуск (для отладки)

```bash
pip install -r requirements.txt
export GMAIL_ADDRESS="you@gmail.com"
export GMAIL_APP_PASSWORD="xxxxxxxxxxxxxxxx"
export MAIL_TO="you@gmail.com"     # опционально
python main.py
```

Логи выводятся в stdout — по ним сразу видно, сколько вакансий вернул
каждый источник и сколько прошло фильтр.

## Ограничения / что нельзя делать (соблюдено в коде)

- Секреты нигде не хардкодятся — только `os.environ` (`mailer.py`).
- Письмо не отправляется, если новых подходящих вакансий нет
  (`main.py`, ранний `return 0`).
- Повторно отправленная вакансия не уйдёт снова — дедупликация по
  `Vacancy.id` (хэш от URL) через `seen_vacancies.json`.
- Падение одного парсера не останавливает остальные — `try/except` и
  логирование на двух уровнях (внутри парсера и в `main.run_all_parsers`).
